1. Role Overview
The Mosque Operating System (MOS) uses a simplified 2-role access control system. All other roles from the original specification have been consolidated into these two roles for clarity and ease of management.
🏠 MOSQUE OWNER
owner | Owner@123
The Mosque Owner is the highest authority within a mosque's account. This role is responsible for claiming the mosque, configuring system-level settings, and delegating management to the Admin.
Claim and own the mosque profile on the platform
Enable or disable modules for the mosque
Configure mosque-level settings (timezone, visibility, feature flags)
Has all Admin permissions in addition to exclusive ownership rights
Cannot be overridden by Admin — Owner is the final authority
⚙️ MOSQUE ADMIN
admin | Admin@123
The Mosque Admin manages the day-to-day operations of the mosque platform. This includes prayer times, events, announcements, madrassah, and all content-related tasks.
Manage all mosque content (prayer times, events, announcements)
Manage madrassah students, attendance, and fees
Post janaza announcements and community content
Manage awrad, duas, and spiritual content library
Create and manage communities and participation opportunities
Cannot change mosque ownership or disable modules

2. SQL Server Database Setup
Below is the complete seed script for SQL Server to create roles and users with correct credentials.
2.1 Create Roles
-- SQL Server: Insert Roles into ASP.NET Identity
INSERT INTO [dbo].[AspNetRoles] (Id, Name, NormalizedName, ConcurrencyStamp)
VALUES
  (NEWID(), 'MosqueOwner', 'MOSQUEOWNER', NEWID()),
  (NEWID(), 'MosqueAdmin', 'MOSQUEADMIN', NEWID());
2.2 Create Users
-- Users are created via ASP.NET Identity UserManager
-- Use this C# seed in Program.cs or a DbSeeder class:
var owner = new ApplicationUser { UserName = "owner", Email = "owner@mosque.com" };
await userManager.CreateAsync(owner, "Owner@123");
await userManager.AddToRoleAsync(owner, "MosqueOwner");
var admin = new ApplicationUser { UserName = "admin", Email = "admin@mosque.com" };
await userManager.CreateAsync(admin, "Admin@123");
await userManager.AddToRoleAsync(admin, "MosqueAdmin");
2.3 Connection String (SQL Server)
// appsettings.json
"ConnectionStrings": {
  "DefaultConnection": "Server=.;Database=MosqueOS;Trusted_Connection=True;MultipleActiveResultSets=true"
}
// Program.cs — EF Core SQL Server registration
builder.Services.AddDbContext<AppDbContext>(options =>
  options.UseSqlServer(builder.Configuration.GetConnectionString("DefaultConnection")));

4. API Authorization Reference
All API endpoints use ASP.NET Core Identity with JWT Bearer tokens and role-based authorization attributes.
4.1 Role-Based Controller Attributes
// Owner-only endpoint
[Authorize(Roles = "MosqueOwner")]
[HttpPost("mosque/claim")]
public async Task<IActionResult> ClaimMosque(...) { }
 
// Admin and Owner both allowed
[Authorize(Roles = "MosqueOwner,MosqueAdmin")]
[HttpPost("prayer-times")]
public async Task<IActionResult> CreatePrayerTimes(...) { }
 
// Public endpoint (no auth required)
[AllowAnonymous]
[HttpGet("mosque/{slug}")]
public async Task<IActionResult> GetMosqueProfile(string slug) { }
